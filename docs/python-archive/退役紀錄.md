## 已知且接受的差異（使用者 2026-10-13 決定：座標一致即可）

約 150 顆孔（20 張圖）的座標與 Python 相同，但 JS 是用不同的規則推導出來的，因此 note 的規則名與信心度也會不同（信心度不同 127 顆，JS 多半偏低）。逐孔清單見 `js-py-parity-6.80.md`，常見的對應如下：

| Python 規則 | JS 規則 | 顆數 |
| --- | --- | --- |
| SECTION VIEW CONVERSION | NO CONVERSION | 22 |
| REPEATED EDGE MARKER ROW + DETACHED DIMENSION | CROSS-VIEW MARKER PAIRING | 18 |
| REPEATED SECTION PROFILE EVIDENCE | CROSS-VIEW MARKER PAIRING | 12 |
| SECTION VIEW CONVERSION | BACK CONVERSION | 12 |
| SECTION VIEW CONVERSION | 同座標不同直徑配對 | 10 |
| NO CONVERSION | SECTION VIEW CONVERSION | 10 |
| TICK MARKER ROW | SCALED SECTION TICK PAIR EVIDENCE | 10 |
| FULL VIEW CONVERSION | FULL VIEW DIRECT CIRCLE | 6 |

影響：

- 信心度只影響回歸的「多出孔」判定，以及畫面上的信心顯示，不影響座標。
- 若日後要讓推導路徑也一致，可以用 `node tools/parity.mjs --rule --conf` 對照 `fixtures/py-reference-6.80/` 逐案追。

## 退役後怎麼驗證

- `npm test`：依序跑比對規則自我測試、合成單元測試、全圖回歸。
- `node tools/parity.mjs`：與 Python 6.80 的最後輸出比對。只當歷史參考：之後 JS 刻意改進的地方會與它不同，不需要追。
- 重新產生合成單元測試圖需要 Python 與 ezdxf（`tools/gen_unit_fixtures.py`）。平常不需要，圖檔已提交。
