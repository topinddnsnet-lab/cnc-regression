# 開發指引（新對話請先讀這份）

這份文件記錄專案的**開發原則**、**使用者（人類）的正確推導**，以及過去踩過的坑。
目的：開新對話時不必重新說明；接手的人（或 AI）讀完就能照同樣的標準繼續開發。

> 最後更新：v1.4.1（2026-09-30）。每次重大觀念變更都要回來更新這份文件。

---

## 1. 專案目標與硬性原則

**目標**：2D 的 DXF 加工圖 → 銑削特徵 → 各面向的加工路徑（一律「路徑」TOOLPATH、G91 子項）。
目的就是**把特徵銑除，並用最少的加工量**。

| # | 原則 | 說明 |
|---|---|---|
| 1 | **只有一套通用規則** | 全專案所有案例共用同一套判斷；選規則的依據是「推導正確的比例最高」 |
| 2 | **禁止硬編碼** | 不看料號、檔名、圖層名稱、固定座標；**回歸設定也不能有案例專屬的判斷規則** |
| 3 | 開發版本不管舊版相容 | 舊邏輯有必要就改或刪 |
| 4 | 路徑與刀具補正分開 | 先算最短路徑（不含刀具），再做刀具補正（選刀、刀心偏移） |
| 5 | Z 與深度不要求絕對正確 | 路徑對、切得掉就好 |
| 6 | 加工面向沒有嚴格要求 | 能把特徵銑掉、加工量最少即可 |
| 7 | 孔不歸這裡管 | 孔由 `external/DXF_Hole_Extractor`（獨立專案）負責，這裡只拿它的結果當量尺；**打包時不要包進去** |
| 8 | 卡住就問 | 人類答案有明顯錯誤、找不到斷面圖佐證時，先問使用者，不要浪費 token 瞎猜；但整體寬容度高，可以自由發揮 |
| 9 | 分次回歸 | 一次跑一個案例（或一層），否則容易逾時 |
| 10 | 版本與日誌 | 小更新 x.y.**z**、功能新增 x.**y**.0、重大變更 **x**.0.0；每次都寫 `CHANGELOG.md` |
| 11 | 使用者偏好 | 繁體中文溝通；Python（另可 JavaScript、PHP 7.4）；註解用繁體中文 Google 風格 Docstring／JSDoc |

## 2. 座標與面向（最重要的觀念）

### 2.1 斷面圖的前後上下 ↔ 四個面向

斷面圖上的四個方向，對應匯入專案的四個面向（標籤）：

| 斷面圖 | 面向 | 名稱 |
|---|---|---|
| 前 | 0° | 0度(正面) |
| 上 | 90° | 90度(頂面) |
| 後 | 180° | 180度(背面) |
| 下 | 270° | 270度(底面) |

### 2.2 真實 3 軸只能從上往下（Z 軸）加工

所以**要加工哪一面，就要先把工件繞料長（X 軸）轉，讓那一面朝上（+Z）**，再用轉完後的座標出路徑。
如果照斷面圖原樣擺成 0°，朝上的是斷面圖的「上」；這時說要加工「前（0°）」，刀子實際會落在「上（90°）」。

程式的做法（`workpiece/model.py`）：每個面向標籤 f ＝ 斷面擠出後繞 X 軸轉 f 度、讓面向 f 朝上，再把最小角落貼回原點。

**工序座標一律是「該面向朝上時」的標籤座標**：

* x：沿料長（0＝前端）；
* y：從 0（靠操作者那側的邊）往負；
* z：從底往上（頂面＝該標籤斷面的最大 z）；
* 起點與 G91 子項都是**刀心**。

與 JS 模擬器的 CAM 節點相同，所以 `_cnc_project.json` 在網頁版打開就是對的。

### 2.3 斷面轉正（通用規則，依序比）

斷面在圖上可能是任何擺法，要決定「轉幾個 90° 才對」（`workpiece/auto.py`）：

1. **孔對上數**：面向 f 的孔（孔位專案給的）要落在旋轉 f 度標籤的材料表面上。
2. **孔校正視圖的實線貼合工件邊比例**（`view_line_fit`）：孔排列對稱時，轉 0° 與 180° 孔一樣多，
   但槽、台階等邊不對稱，只有正確轉法會讓圖上的線貼齊工件邊。
3. **斷面圖方向**（`orientation_prior`）：先把料高（Z）轉成橫向（圖上寬高對調就順時針轉 90° 看），
   再以「上＝90°、右＝0°」。只在前兩層都分不出來時才用（例：沒孔也沒可校正的視圖）。

三個案例三層結論一致：NTN007 轉 90°、PYN09 轉 90°、C3N405 轉 0°（視圖貼合 0.99 對 0.33）。

### 2.4 料長方向（鏡射）：看端視圖在主視圖哪一邊（使用者規則）

**側視圖（端視圖）畫在主視圖右邊，以斷面圖擠出的工件就要做鏡射**（x → L − x）；畫在左邊不用鏡射。

* CJN38：端視圖在右 → 鏡射。圖上左端特徵 30、右端 50，人工答案是左 50、右 30。
* NTN007：斷面來源是下方的剖視，不在主視圖旁邊 → 不鏡射。
* 優先順序：孔左右不對稱就由孔決定；孔對稱或沒有孔才用這條（v1.4.0 起孔對稱時也會套用，例 EW-N06E）。

### 2.5 視圖校正

有孔的視圖用孔當量尺；沒有孔的視圖用「線貼工件邊」，**實線與隱藏線都算**（隱藏線是另一側的邊，能分出正面／背面）。

## 3. 人類的推導（已驗證正確的部分）

以下是使用者（人類）判斷特徵與規劃路徑的方式，程式照這套邏輯實作。

### 3.1 特徵邊界從哪裡看

* **除了最長的（工件長度）以外的垂直線**：特徵在料長方向的邊界。
* **不連續線**：平行料長、但沒有從頭畫到尾的線；斷開的地方就是特徵。
* 這兩種線圍出的「圖上沒畫材料」的區域＝要去掉。
* 封閉小輪廓（例：凸緣邊上畫成小矩形的槽）也是特徵，但深度方向的位置要看**斷面圖的剖面線**。
* **隱藏線（虛線）也是邊界**：特徵在另一側時主視圖只畫成隱藏線，外框是完整矩形；
  一樣看「非料長端的垂直線＋從那裡才開始的不連續線」（CJN38：x=30、1060 的隱藏垂直線）。
* **帶子的一條邊可能與本體的面齊平**（EW 凸耳）：那條是全長線，只要另一條邊斷開就是特徵；
  兩條邊都是全長線（NTN007 凸緣帶）才不是。
* 沒有剖面線時，帶內只取**凸出物**；兩側同高度都有材料延續的是貫穿的壁。
* 修訂雲（粗弧線圈起來的範圍）只是標示修改處，不是工件的線。
* 圖上的孔（孔位專案已辨識的）不算銑削特徵；沉頭孔在側面投影成好幾個小矩形，也都是孔。
* 找不到斷面圖佐證時，要問使用者。

### 3.2 選面：象限法＋最少加工量

把斷面當成一個盒子，以中心為原點：

| 象限 | 位置 | 候選面向 |
|---|---|---|
| I | TOP、FRONT | 90、0 |
| II | TOP、BACK | 90、180 |
| III | BOTTOM、BACK | 270、180 |
| IV | BOTTOM、FRONT | 270、0 |

先看特徵在哪個象限，再細分要從哪一面加工：比各面向**實際要切掉的材料體積**，最少者勝。

典型判斷（NTN007）：U 形槽的兩隻腳在底部，一隻偏前（IV）、一隻偏後（III）。
從底面整塊挖要切 35 深；從側面沿邊界切斷只要切腳的厚度 → 前面那隻從正面、後面那隻從背面。

**不能過切其他特徵**（使用者：「為何不用底面、頂面、背面？因為會過切其它特徵」）：
刀從面向頂面下來、一路到特徵底，經過的地方（含刀寬掃到的範圍）有要保留的材料就不能從那面加工。
CJN38 的臂：底面會掃到牆下的 H 形腳、頂面被 Z 形擋、背面被牆擋 → 只剩正面（程式自動判出）。
CJN39 同類斷面但臂根部可從底面沿接觸邊切斷（2280 mm³）比正面挖除（7400 mm³）省 → 底面（與人工一致）。

### 3.3 路徑：走最短路徑、讓整塊掉下來

* 不必把特徵整塊銑掉；**沿著「特徵與保留材料接觸的邊界」切一刀，讓那塊掉下來**（切斷）。
* 路徑從料外進刀、沿接觸邊走、再走出料外。典型是 L 形：兩條接觸邊（一條料長方向的端面、一條側面）。
* 四邊都接觸（例：板上的槽）＝封閉輪廓，切一圈料心掉下來。

### 3.4 刀具補正（與路徑分開）

* 可用刀徑 10／6／4，挑放得進去的最大一把；刀號對照 Ø10→T5、Ø6→T6、Ø4→T11。
* 刀心往特徵內側偏刀半徑 r（刀緣剛好貼著邊界線）。
* **開放端（落在料外）沿路徑方向外延 r**，刀子完整走出料外。
* 槽寬＝刀徑時，封閉輪廓退化成**中心線**，單趟走完。
* **刀可以比特徵寬**，只要多掃到的都是空氣：CJN38 的臂只有 5 寬，人工用 Ø10 沿中心線 (-5,-21.5)→(45,-21.5)，
  料外那端外延 r、接觸那端內縮 r。
* 深切分次下刀：CJN38 切 69 深、Ø10、分 4 次（每次 ≤ 2 × 刀徑）。
* **垂直線清角（泛用規則）**：中心線走到接觸端（垂直邊界線）後，沿那條垂直線橫掃，刀心超出帶子兩側各 r，
  把角清乾淨；**從料外進刀**，最後才清角。多掃到的範圍必須是空氣，否則不清（例：板上的槽）。
* **深度分層**：特徵斷面寬度隨深度改變時要分層，各層各自決定中心線與清角寬度，
  才不會在窄的那層掃到旁邊的保留材料（CJN38：小勾層清到 ±7.5、臂層只清到 +6／−6，停在上方 Z 形下緣）。

範例（CJN38，臂尖小勾層、Ø10）：

```
起點 (-5,-21.5)，G91：X+50（中心線到接觸端 x=45）、Y+7.5（清到帶子上緣外 r）、Y-15（清到下緣外 r）
```

範例（NTN007，Ø10，缺口 x 0～20、y -172～-137）：

```
最短路徑（邊界上）：(20,-172) → (20,-137) → (0,-137)
刀心路徑（補正後）：(15,-177) → (15,-142) → (-5,-142)      ← 內縮 5、兩端外延 5
G91：起點 (15,-177)，子項 Y+35、X-20
```

範例（NTN007，槽 394～406 寬 6，Ø6）：刀心 (397,-95) → (403,-95)。

### 3.5 Z 與深度

Z＝切削層頂（特徵在該面向的最高點），深度＝特徵厚度＋餘量。不要求絕對正確。
餘量看特徵底下：**底下是空氣 1mm**（NTN007 槽腳、凸緣槽）；**底下是要保留的本體 0.2mm**，只掃一層皮、不切進本體
（EW 凸耳 -2.2、CJN38 臂 -69）。

## 4. 程式架構（v1.2 起）

```
DXF ─ 孔位專案（量尺） ─ 自動建 3D（斷面轉正 §2.3、料長、斜切、四個標籤） ─ 視圖校正
    └─ 邊界引擎 dxf_feature_extractor/boundary/（預設採用）
         1 view_regions  視圖邊界 → 區域（§3.1）
         2 evidence      斷面剖面線 → 斷面座標
         3 chunks        區域 → 斷面連通塊（去除區塊）
         4 faces         象限法＋加工量選面（§3.2）
         5 minpath       最短路徑（不含刀具，§3.3）
         6 compensation  選刀＋刀心補正（§3.4）
    └─ 路徑規劃（JS 移植，workpiece/planner.py）：只補邊界引擎沒涵蓋的材料
         （舊工序 50% 以上落在邊界區塊裡、或同面同帶多切超過一個刀徑 → 只留參考）
    └─ 正視圖規則（舊版）：只當參考，不採用
```

## 5. 回歸測試

案例放 `tests/fixtures/regression/<案例>/`：

| 檔案 | 內容 |
|---|---|
| `source.dxf` | 圖 |
| `expected.json` | 人類標準答案（v2 shapes 格式：`{"version":2,"tabs":[…],"shapes":[…]}`） |
| `case.json` | **只放人工答案的註記**（`note`、`known_issues`、`pending`），不能放判斷規則 |

逐條人工路徑由便宜到貴判定，前一層過就不跑後面（可單用或混用）：

| 層級 | 方法 | 門檻 |
|---|---|---|
| L1 座標 | 同面向、同刀徑、刀心折線一樣（可反向，±0.6mm） | 全等 |
| L2 面積 | 同面向往下看，人工刀具掃過面積被程式覆蓋 | ≥80%（程式可以多） |
| L3 體積 | 在程式的 3D 工件上實切，人工這條去掉的材料程式也去掉 | ≥80% |
| 全案 | 關鍵去除體積：召回／程式÷人工 | ≥80%／≤2 |

全部 L1 通過就略過全案體積，但仍檢查**多出工序**：沒對上人工的程式工序掃過面積合計 ≤ 人工 2 倍
（程式可以多，但不能多到亂切）。面向一律**照名稱**對照。

```
python tools/regress.py --list
python tools/regress.py NTN007-033                 # 一次一個案例
python tools/regress.py NTN007-033 --levels coord  # 只比座標（最快）
python tools/regress.py C3N405-1AE05 --face-map auto   # 診斷：面向是否標反（測試不用）
python -m pytest -q tests/test_regression.py -k NTN007
python -m pytest -q --ignore=tests/test_regression.py  # 其他測試
```

分析結果依「DXF＋原始碼雜湊」快取在 `.regression_cache`，同一版程式第二次不重算。

### 5.1 新案例的流程

1. 建 `tests/fixtures/regression/<料號>/`，放 `source.dxf`、`expected.json`。
2. `python tools/regress.py <料號>`，看報告。
3. 不通過時，先分清楚是**程式錯**還是**人工答案筆誤**（見 §6.1），人工疑點問使用者確認後才改 `expected.json`。
4. 修程式時，**其他案例要一個一個重跑**，確認沒退步。
5. 更新版本號、`CHANGELOG.md`、本文件（有新觀念時）。
6. 打包時排除 `external/DXF_Hole_Extractor`、`__pycache__`、`.pytest_cache`、`.regression_cache`。

## 6. 經驗與陷阱

### 6.1 人工答案也會有筆誤：用圖面幾何判斷，問過再改

已發生過的筆誤（已確認並修正）：

| 案例 | 筆誤 | 怎麼發現 |
|---|---|---|
| NTN007-033 | 第 2、3 個槽起點 694／994（應為 697／997） | 圖上槽中心 700／1000、間距 300；第 1 個槽 397 是對的 |
| C3N405-1AE05 | 90／270 標籤相反 | 照名稱召回 22%；對調後人工去掉的材料程式 100% 都去掉；圖面幾何支持程式的轉法 |
| EW-N06E-617 | 右端長度 40（應為 35） | 圖上尺寸左 35、右 40，端視圖在右＝鏡射 → 實際右端 35 |

待確認（使用者要求先不修正）：EW-N06E-617 面向 0°（程式）對 180°（人工），座標相同；`case.json` 的 `pending`。

原則：

* **不要為了遷就錯的答案去改程式或加案例例外**（v1.2.0 曾替 C3N405 設 `face_map: auto`，違反原則 1，已移除）。
* 用圖面幾何（線、剖面線、孔、標註間距）驗證；證據明確就列出來問使用者，確認後修正 `expected.json` 並記在 `CHANGELOG`。

### 6.2 不要相信自己的中間結論，要回到幾何驗證

v1.2.1 曾以為 C3N405 轉 180° 才對，其實是被人工筆誤誤導；檢查「正視圖上沒畫材料的帶子，對到斷面上的材料是否合理」才發現 0° 才對。
**規則要以圖面推導的正確率來選，而不是以「符合某份答案」來選。**

### 6.3 技術陷阱

* **GUI 圖面只有對上視圖的面向**：其他面向的工序要用 `workpiece/projection.py` 投影過去，否則不畫也不高亮（v1.2.3 修正）。
  改 GUI 後用 `xvfb-run -a python tools/gui_snapshot.py 圖.dxf 輸出 --pick B1,B2,…` 截圖做視覺確認。
* **GUI 行為要能開關**：會改變使用者視野的自動行為（例：選取時自動放大）要放進設定、可關閉，並存到 QSettings。

* **點陣對不齊**：四個面向各自點陣化，換算時區塊邊上會多出一兩格「保留材料」，造成假接觸（誤判成只能挖除）。
  → 保留材料的碎塊（< 12 格）不算、接觸至少 3 格才算（`boundary/faces.py`）。
* **校正的小數誤差**：視圖校正會有 0.01～0.05mm 誤差（例 19.96）→ 吸附到 0.5 的倍數（`engine.snap`）。
* **對分時程式工序要用後處理的 Z／深度**：程式工序的 Z／深度常是 None；模擬要用 `scoring.op_path`（有切削目標用目標，否則用後處理值），
  否則 PYN09 會從 98.9% 掉到 0.6%。
* **判斷重複工序的分母**：舊規劃的長條切斷（190 長）只和新引擎的缺口（20 長）部分重疊時不算重複 → 分母只用舊工序自己的面積。
* **v2 shapes 格式沒有工件模型**：對分用程式自己建的標籤；座標系與人工一致的前提是轉正正確（§2.3）。
* **寫檔要用 `with`**：`json.dump(d, open(p, 'w'))` 在同一個腳本裡接著讀會讀到舊內容。
* **舊規劃（JS 移植）會沿整條帶亂切**（CJN38／39 沿臂全長 1100～1600mm）：以「特徵所在視圖」判斷，
  同面或背面、同一條帶超出邊界引擎區段就不採用；不要只比對區塊最後選的加工面。
* **回歸通過不代表沒有亂切**：座標全等會略過全案體積，靠「多出工序」檢查補上。
* **GUI 的奇怪線段**多半是「把圖上別的東西當特徵」的工序（斷面詳圖輪廓等）：路徑大部分在工件外就判無效、不畫不列。
* **自動面向對照（`--face-map auto`）不一定能診斷面向相反**：人工路徑放在錯的面也可能切到材料（EW 背面切到管壁 1105mm³）。
  要確認時，把人工路徑手動放到懷疑的面實切比較。
* 改規則時要注意**放寬一條規則會讓別的案例多出假特徵**（v1.4.0 放寬帶邊全長線時 NTN007 多出兩個假區域），
  每次都要全部案例重跑並看「多出工序」。
* **v1.1 的例題回歸**（`tests/test_examples.py`）需要環境變數 `DXF_FEATURE_EXAMPLES` 與人工 JS 專案，平常會略過；主要回歸看 `tests/test_regression.py`。

### 6.4 新案例帶出規則的做法（CJN38 的例子）

1. 先看圖（`/home/claude` 以外的環境可用 `tools/render_view.py`；或 ezdxf＋matplotlib 局部放大），找出特徵的線證據；
2. 對照人工答案找出「人類怎麼推」（例：左右相反＝鏡射；不用底面＝會過切）；
3. 寫成**不看案例的通用規則**，再用全部舊案例逐一重跑確認沒有退步；
4. 規則與理由寫進本文件。

## 7. 已知限制

* PYN09 正面 45° 斜切端旁的斜向路徑規劃不出來（邊界引擎與 JS 規劃都不行），需人工補。
* 邊界引擎的區塊外框假設是矩形（料長區間 × 橫向範圍）；非矩形區域（填滿率低）還沒拆解。
* 封閉小輪廓沒有剖面線佐證時，退而取最靠近視線的那塊材料（標記待複核）。
* 孔左右對稱、特徵不對稱、端視圖又不在主視圖旁邊時，料長方向沒有證據（目前取同向）。
