# DXF 銑削特徵辨識（dxf_feature_extractor）v1.4.1

> **新對話／新開發者請先讀 [`開發指引.md`](開發指引.md)**：開發原則、座標與面向觀念、人類推導、回歸方法與踩過的坑。

由 DXF 加工圖辨識銑削特徵，規劃**各面向**要走的「路徑」（加工類別一律「路徑」TOOLPATH，G91 表格）。
不做孔、不做圓：孔位由獨立的外部孔位專案負責，這裡只拿它的結果當「量尺」。

## 流程

```
DXF ─┬─ 外部孔位專案 CLI（external/DXF_Hole_Extractor）→ 孔＋料長／寬／高（只當量尺）
     │
     ├─ 自動建 3D：切斷面 → 轉正（面向 f 的孔落在旋轉 f 度標籤的材料表面）→ 料長 → 斜切
     │            → 四個面向標籤 0度(正面)／90度(頂面)／180度(背面)／270度(底面)
     ├─ 視圖 ↔ 面向校正：圖上的圓對上各面的孔（孔只一排時用線貼工件邊決定方向）；沒孔的視圖用線對工件邊
     ├─ 邊界引擎（v1.2，預設）：視圖邊界 → 區塊 → 象限＋加工量選面 → 最短路徑 → 刀具補正
     ├─ 路徑規劃（JS 特徵層移植，補漏）：構件 → 成品圖對照（圖上沒畫的段＝要去掉）→ 端部清空帶／切斷連接／立片／長槽
     │            → 每條候選都在斷面點陣上沿料長實際切一次，挑「整段去掉、不壓牆、進出刀在料外」的走法
     └─ 正視圖規則（舊版，參考）：水平線中斷（T／I 含 Y 向橫槓）、端點外垂直線、內輪廓…
          → 換到前視圖對上的面向；有規劃結果時預設不採用
                                    │
                         路徑工序（父項：面向、X、Y、Z、深度；子項：G91）
                                    │
                    後處理補參數（Z、深度、安全高、R 點、下刀次數、刀號）
                                    │
            _ops.json（樹狀）／_cnc_project.json（JS 模擬器直接開）／GUI 審核
```

## 核心原則

| 原則 | 做法 |
|---|---|
| 一律路徑 | 每道工序＝面向＋起點（刀心）＋G91 子項；長槽也走中心線路徑 |
| 面向＝裝夾 | 面向代號＝JS 自動建標籤的旋轉角；座標＝該標籤座標（x 沿料長、y 0→負、z 往上） |
| 專心算路徑 | Z 可以不準、加工參數不預填；後處理補（規劃建議值 → 預設值），補了哪些看 `post.filled` |
| 程式多算、人少算 | 走法全部由程式產生並模擬；人（或 GUI）只挑選、微調 |
| 只靠推導 | 不看料號、檔名、圖層名稱或固定座標 |
| 孔位獨立 | 孔位專案放 `external/`，只呼叫 CLI；更新時整個資料夾覆蓋 |

## 面向與座標

| 面向 | 名稱 | 標籤旋轉 rotationX |
|---|---|---|
| 0 | 0度(正面) | 0 |
| 90 | 90度(頂面) | 90 |
| 180 | 180度(背面) | 180 |
| 270 | 270度(底面) | 270 |

工序座標是**該面向朝上時**的標籤座標：x 沿料長（0＝前端）、y 從 0（靠操作者那側的邊）往負、z 從底往上。
起點與 G91 子項都是刀心。與 JS 模擬器的 CAM 節點完全相同，所以 `_cnc_project.json` 在網頁版打開就是對的。

## 路徑規劃（JS 特徵層移植）

| 模組 | JS 來源 | 做什麼 |
|---|---|---|
| `workpiece/model.py` | WorkpieceModel.js | 斷面擠出＋旋轉＋斜切的純幾何：探測線、點陣化、跨標籤換算 |
| `workpiece/profile.py` | ProfileExtractor.js | 從圖切出斷面（封閉多段線或 REGION），貼著外輪廓的封閉線不當內腔 |
| `workpiece/auto.py` | AutoWorkpiece.js、FaceMatch.js | 斷面轉正、料長（斷裂視圖用標註長度）、斜切偵測、四個標籤 |
| `workpiece/calibration.py` | ViewCalibration.js、drawingLink.js | 視圖 ↔ 面向校正 |
| `workpiece/candidates.py` | CutCandidates.js | 構件（M1…）：懸臂板（沿牆切斷）、立片（從上面銑） |
| `workpiece/extent.py` | DrawnExtent.js | 成品圖對照：構件邊線畫到哪、毛料有到哪；端部清空帶 |
| `workpiece/simulator.py` | CutSimulator.js | 沿料長取斷面切一次、三維連通，判斷掉下來的塊、壓牆、進出刀 |
| `workpiece/planner.py` | PathPlanner.js、workpieceTools.proposalsOf | 產生並模擬每條路徑建議 |
| `workpiece/mesh.py` | （DxfExtruder／BevelCutter 的幾何） | 3D 擠出網格與切削痕跡 |

## 邊界引擎（v1.2，預設採用）

```
已校正視圖 ──► 1 視圖邊界 → 區域 ──► 2 斷面剖面線佐證 ──► 3 去除區塊（斷面連通塊×料長區間）
                (view_regions)          (evidence)              (chunks)
          ──► 4 象限法＋加工量選面 ──► 5 最短路徑（不含刀具） ──► 6 刀具補正 ──► 工序
                (faces)                   (minpath)                 (compensation)
```

| 步驟 | 做什麼 |
|---|---|
| 1 視圖邊界 | 實線當牆（**料長端以外的垂直線**、**不連續線**、圓），從毛料外灌水，灌得進毛料範圍的＝沒畫材料＝要去掉；封閉小輪廓另收（孔位專案已有的孔排除） |
| 2 剖面線 | 各份斷面圖的 HATCH 換到斷面座標，決定封閉特徵（例：凸緣上的槽）在深度方向的位置 |
| 3 區塊 | 區域的 y 帶在斷面上的材料，拆成連通塊（U 形槽兩隻腳各一塊，各自選面） |
| 4 選面 | 象限（I TOP/FRONT、II TOP/BACK、III BOTTOM/BACK、IV BOTTOM/FRONT）給候選；比各面向實際切到的材料：切斷＝刀寬沿接觸邊掃過，坐在保留材料上＝整塊挖除，上方有保留材料＝不可 |
| 5 最短路徑 | 俯視外框上「接觸保留材料」的邊串成折線、兩端落在料外；四邊接觸＝封閉 |
| 6 刀具補正 | 10／6／4 挑放得進去的最大一把；內縮 r、開放端外延 r；寬＝刀徑時退化成中心線 |

最短路徑（`details.minPath`）與刀心路徑（工序本身）分開存；換刀只重算第 6 步。
路徑規劃（JS 移植）只補邊界引擎沒涵蓋的材料（工序 50% 以上落在邊界區塊裡就只留參考）。

## 回歸測試（tests/fixtures/regression）

每個案例一個資料夾：`source.dxf`、`expected.json`（人工，v2 shapes）、`case.json`（只放人工答案的註記：
`known_issues` 單條疑點、`pending` 整份待確認）。**判斷規則全案例共用，不能有案例專屬設定**；面向一律照名稱對照
（`tools/regress.py --face-map auto` 只供診斷面向是否相反）。

| 層級 | 方法 | 門檻 |
|---|---|---|
| L1 座標 | 同面向、同刀徑、刀心折線一樣（可反向，±0.6） | 全等 |
| L2 面積 | 同面向往下看，人工刀具掃過面積被程式覆蓋 | ≥80% |
| L3 體積 | 程式 3D 工件上實切，人工這條去掉的材料程式也去掉 | ≥80% |
| 全案 | 去除體積召回／程式÷人工 | ≥80%／≤2 |

逐條由 L1 往後，過了就不跑後面；全部 L1 通過就略過全案體積。分析結果快取在 `.regression_cache`。
**一次跑一個案例**（避免逾時）：

```
python tools/regress.py --list
python tools/regress.py NTN007-033
python tools/regress.py NTN007-033 --levels coord
python -m pytest -q tests/test_regression.py -k NTN007
```

## 正視圖規則（舊版，參考）

沒有外部孔位專案（或建不出 3D）時，只剩這一套；面向暫放 0度(正面)。

**T／I 特徵的 Y 向連續銑削（v1.1）**：水平線中斷的封閉端若有垂直線（高度 ≥ 最小刀徑），
那一端沿 Y 上下走完整條橫槓。T＝一端開放（從端面外進刀）、另一端橫槓；I＝兩端封閉、兩端都有橫槓：

```
T：  ────────────┐          I：  ┌────────────┐
    (料外進刀)    │ ← Y 上下       │            │ ← 兩端都 Y 上下
                 ┘               └            ┘
```

橫槓刀心在斷開端往內 r；落在工件外框的橫槓端外延 r 出料外，其餘內縮 r。

### 正視圖規則（參考路徑）

特徵只出現在兩種地方：

1. **水平線中斷**：同一 Y 層的水平線在工件長度內斷開。
2. **非前後端點的垂直線段**：X 不在工件前、後端面上的垂直線段。

依這兩條規則，正視圖被拆成下列路徑來源：

| 來源 | 條件 | 最小路徑 | 形狀參考 |
|---|---|---|---|
| 外輪廓偏離 `contour` | 外輪廓上不在外框四條邊上的連續邊，且含水平中斷或端點外垂直線 | 該段輪廓鏈（兩端落在外框上） | STEP／U |
| 封閉內輪廓 `pocket` | 外輪廓內的封閉輪廓 | 輪廓本身（封閉） | RECT／L／…（JS 分類） |
| 水平線中斷 `gap` | 開放水平線，以及比最小刀徑還細的封閉細條（取中心線）；同一 Y 層的每個斷開區間 | 斷開區間的直線 | 碰端面＝T、兩端封閉＝H |
| 端點外垂直線 `vertical` | 不屬於任何輪廓、且不在前後端面的垂直線 | 該線段 | LINE |
| 長圓孔 `slot` | JS 形狀分類為 CAPSULE | 不轉路徑 | SLOT |

另外兩條排除規則：

- **倒角、外圓角**只有斜邊或圓弧，既沒有水平中斷、也沒有端點外垂直線，不輸出。
- **內輪廓的中心線**（非實線、中點落在內輪廓中心）是對稱標記，不是邊，不輸出。

「形狀參考」只是給人看的名稱，不參與任何判斷。

#### 正視圖規則的刀具後處理

**選刀**：可用刀徑只有 **10／6／4 mm**。

- 一般一律用 **10**。
- 10 會過切（大於路徑可用的最窄寬度）時改用 **6**。
- 6 仍會過切才用 **4**。
- 連 4 都會過切時，仍給 4 並標記 `OVERCUT_UNAVOIDABLE`，狀態設為待複核。

「最窄寬度」由辨識層量出：U 槽開口寬、內輪廓短邊、兩端封閉的中斷區間長度、長圓孔寬度。沒有限制時為 ∞。

**刀心補正**：

| 路徑 | 刀心路徑 |
|---|---|
| 沿輪廓（contour／pocket） | 往材料反側平移刀半徑 r，尖角以斜接連接；開放端（落在工件外框上）再外延 r |
| 沿線切削（gap／vertical） | 刀心在線上；開放端外延 r，封閉端內縮 r（刀緣剛好到端點） |
| 長圓孔 | 刀心中心線（兩端圓心之間）；刀徑小於孔寬時標記 `SLOT_NEEDS_SIDE_PASS` |

GUI 表格的「刀徑」欄可以直接改。改了只重算刀心路徑，最小路徑不變。


## 後處理

| 欄位 | 工序沒填時 |
|---|---|
| Z | 規劃建議（切削層頂面＝JS「自動向下貼齊」的結果）→ 該面向頂面 |
| 深度 | 規劃建議（切削層厚、端部清空帶寬）→ 預設 -10 |
| 安全高／R 點／下刀次數 | 50／5／1 |
| 刀號 | Ø10→T5、Ø6→T6、Ø4→T11 |

預設值在 GUI「設定」改。GUI 樹裡括號中的灰字＝後處理補的值；雙擊父項填了數字就以填的為準。

## 使用

安裝依賴（外部孔位專案的依賴也要裝在同一個環境）：

```
pip install -r requirements-gui.txt
pip install -r external/DXF_Hole_Extractor/requirements-gui.txt
```

CLI：

```
python -m dxf_feature_extractor 圖面.dxf [輸出資料夾] [--hole-dir 孔位專案] [--holes-json X_holes.json] [--no-holes]
```

GUI：`python -m dxf_feature_extractor --gui`（Windows 可雙擊 `run_gui.pyw`）。

### GUI

- 上方：「圖面／面向俯視／3D」切換（Ctrl+1～3，Ctrl+D 切 2D/3D）、面向篩選、刀具帶／切削痕跡、只顯示採用。
  - 圖面：對上視圖的面向直接畫回圖紙；其他面向（例：正視圖對上 0°，背面、頂面的工序）用 3D 換算**投影**到圖面，
    刀心線畫點線、標籤加面向（例「B1(180°)」），選取時一樣高亮；特徵在視野外或太小時自動移過去並放大
    （可關閉：「設定 → 選取時自動放大到位置」或設定對話框的「顯示」，會記住）。
  - 面向俯視：自動建好的工件從該面朝上往下看（顏色越深越低），疊上該面向的工序。
  - 3D：工件（含斜切）、刀心線、G00、切削痕跡；選的面向朝上。
- 右側「路徑樹」：父項＝工序、子項＝G91。點父項整條高亮、點子項只高亮那一段；雙擊編輯；右鍵增刪移動。
- 檔案：F5 分析、Ctrl+S 輸出全部、Ctrl+Shift+S 只輸出勾選、Ctrl+I 匯入改過的 `_ops.json`。

### 輸出檔

| 檔案 | 內容 |
|---|---|
| `<檔名>_ops.json` | 面向＋樹狀路徑（父項＋children G91），`post` 是後處理參數、`details` 是依據與模擬結論 |
| `<檔名>_cnc_project.json` | JS 模擬器專案（四個標籤＋TOOLPATH 節點），網頁版「開啟專案」即可看 3D |
| `<檔名>_paths.json`／`_toolpaths.json` | 正視圖規則的最小路徑／刀心路徑（舊格式） |
| `<檔名>_feature_summary.json` | 圖紙、視圖、JS 掃描統計、日誌 |
| `<檔名>_corrected.json` | GUI 只輸出勾選的工序（同 `_ops.json` 格式） |

## 已知限制

- 斷面轉正（通用規則，依序）：①孔對上數 ②孔校正視圖的實線貼合工件邊 ③斷面圖方向（料高橫放後 上＝頂面、右＝正面）。
  孔排列對稱（例 C3N405）時由②決定並記在日誌；仍判反時可用「設定 → 斷面轉正後再轉 180°」。
- 人工專案的標籤命名不一定等於旋轉角（C3N405 人工名為「90度(頂面)」的標籤 rotationX＝270）；本程式一律「面向＝旋轉角」，
  回歸照名稱比對，這類人工答案列為 `pending` 待確認。
- PYN09 正面 45° 斜切端旁的那一刀（人工 0° 斜向路徑）規劃不出來（JS 相同），需人工補；在樹上右鍵「新增工序」即可。
- 構件沒有直立牆面、成品圖對照為 shared／hidden 時不出建議（沿用 JS 的保守原則：寧可少一刀，不誤切）。
